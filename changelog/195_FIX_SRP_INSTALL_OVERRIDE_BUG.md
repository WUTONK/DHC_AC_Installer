# 修复模组安装路径错位及目标覆写逻辑 (SRP 0.9.3 安装 Bug)

## 更新内容

1. **修复 `dft.json` 中的 `target` 字段解析缺失**
   - **问题**: 在处理 `Rule` 匹配规则时，底层的 `Rule` 结构体缺少对 `"target"` 字段的 JSON 解析标签，导致写在配置文件中的目标重定向规则被忽略。
   - **修复**: 在 `models/service/decompression/dft.go` 的 `Rule` 结构体中添加了 `Target string ` + "`json:\"target\"`" 字段，并在应用决策阶段使 `hits[0].Target` 成功接管文件树节点的后续安装映射。

2. **移除高危的目录自毁式覆盖逻辑**
   - **问题**: `Overwrite` 函数中如果判断目标目录已存在，会直接调用 `os.RemoveAll(dstPath)`，将玩家已有的目标文件夹（例如整个 `Assetto Corsa/content`）全部彻底删掉再写入，引发毁灭性的灾难。
   - **修复**: 移除了针对 `dstPath` 的自毁检查，仅保留了父目录创建及由 `filepath.WalkDir` 接管的安全覆盖合并逻辑。

3. **修复解压目录被强制整体打包的错误剪枝逻辑**
   - **问题**: `computeUniformInfo` 树形合并判断存在逻辑缺陷，当类似 `content` 这种中间目录仅有一个有效子节点（如 `tracks`）且该节点受到重定向影响时，`content` 会无脑被认为是“整齐划一”的，直接被整体剪枝打包进了重定向目标。此外，根节点 `.` 的兜底逻辑错误地使用根目录名字包装所有文件。
   - **修复**: 
     - 在 `overrideControl.go` 增强了对一致性的计算逻辑：禁止在继承或父节点动作不一致的情况下盲目“上提”决策合并剪枝。
     - 子节点路径现在在决策下沉时会沿用 `filepath.Join` 去计算它原本动态继承的目标。
     - 移除了 `buildTarget` 中如果为 `.` 自动多包一层外壳的错误兜底逻辑，实现了对已经具备标准结构模组（设置 `overwriteStartingDir: "."` 时）的零损耗透明式覆盖。
